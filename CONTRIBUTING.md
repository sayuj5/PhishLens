# Contributing to PhishLens

First off, thank you for considering contributing to PhishLens! It's people like you that make open source such a great community.

## Development Workflow

### 1. Branch Naming
Please use the following conventions for branch naming:
- `feature/your-feature-name`
- `fix/your-bug-fix-name`
- `docs/documentation-update`

### 2. Commit Conventions
We follow [Conventional Commits](https://www.conventionalcommits.org/).
- `feat:` for new features
- `fix:` for bug fixes
- `docs:` for documentation changes
- `refactor:` for code refactoring
- `test:` for adding or updating tests

### 3. Coding Standards
- Ensure all code is properly formatted (Prettier for JS/TS, Black for Python).
- Remove all `console.log()` statements before committing.
- Do not leave unused imports or dead code.

### 4. Pull Requests
- Fill out the provided Pull Request template completely.
- Keep PRs focused on a single issue or feature.
- Ensure all CI checks pass (if configured).

We look forward to reviewing your contributions!
